## What Was Implemented

### 1. Docker Infrastructure
- `docker-compose.yml` orchestrates two services: `db` (PostgreSQL 16 + pgvector) and `api` (FastAPI).
- The `db` service uses the official `pgvector/pgvector:pg16` image — no manual PostgreSQL installation required.
- The `api` service is built from our custom `Dockerfile` (Python 3.11-slim).
- A healthcheck on the `db` service (`pg_isready`) ensures the API container only starts after the database is confirmed healthy.
- A named Docker volume (`pgdata`) persists database data across container restarts.

### 2. Python Virtual Environment
- A `.venv` was created inside `backend/` using `python -m venv .venv`.
- All commands use `.venv\Scripts\<tool>` explicitly to ensure the correct environment is always used.
- `requirements.txt` is fully pinned with all dependencies.

### 3. Pydantic Settings (`app/config.py`)
- All environment variables are validated at startup via `pydantic-settings`.
- If a required variable (`DATABASE_URL`, `OPENAI_API_KEY`, `API_BEARER_TOKEN`) is missing, the application **fails fast** at startup with a clear error — not silently at runtime.
- `SIMILARITY_THRESHOLD` has `ge=0.0, le=1.0` bounds enforced by Pydantic.

### 4. SQLAlchemy ORM Models (`app/models/`)
- `database.py`: Creates the async engine (`create_async_engine`), session factory (`async_sessionmaker`), and `Base` (declarative base).
  - `pool_size=10`, `max_overflow=20`, `pool_pre_ping=True` configured for production readiness.
- `survey.py`: Defines two ORM models:
  - `Survey`: Standard relational table for CRUD with JSONB for the full topology.
  - `SurveyCache`: Vector cache table with a `Vector(1536)` column from `pgvector.sqlalchemy`.

### 5. Alembic Migrations
- Configured for **async** usage via `async_engine_from_config` in `alembic/env.py`.
- `alembic/script.py.mako` template was manually created (it is NOT generated by `alembic init` — it must be added manually).
- Migration `23beccb1c3be` was applied successfully, creating both tables.

## Bugs Encountered & Fixes

### Bug 1: `ModuleNotFoundError: No module named 'app'`
- **Cause:** Alembic was run without setting `PYTHONPATH`, so Python couldn't resolve the `app` module.
- **Fix:** Always prefix Alembic commands with `$env:PYTHONPATH = "."` in PowerShell.
- **Permanent fix for future:** Can add a `[tool.alembic]` section in `pyproject.toml` or set PYTHONPATH in the shell profile.
- **Command pattern:**
  ```powershell
  $env:PYTHONPATH = "."; .venv\Scripts\alembic upgrade head
  ```

### Bug 2: Autogenerate produced empty `pass` migration
- **Cause:** The SQLAlchemy models in `app/models/survey.py` were never imported before Alembic scanned `Base.metadata`. Models must be **imported** for SQLAlchemy to register them in `Base.metadata`.
- **Fix:** Added explicit model import in `alembic/env.py`:
  ```python
  from app.models import survey as _survey_models  # noqa: F401
  ```
- **Rule:** Every time a new SQLAlchemy model file is created, it MUST be imported in `alembic/env.py` using this pattern.

### Bug 3: `type "vector" does not exist`
- **Cause:** The `pgvector` PostgreSQL extension was not enabled inside the database. The Docker image includes the pgvector binary, but the extension must be activated per-database.
- **Fix:** Ran manually:
  ```sql
  CREATE EXTENSION IF NOT EXISTS vector;
  ```
- **Permanent fix:** The `CREATE EXTENSION` command must be added to the Alembic migration's `upgrade()` function so it runs automatically in any new environment. This has NOT been done yet — it is a **known debt** for the next phase.

### Bug 4: Stale `alembic_version` row after deleting migration file
- **Cause:** When we deleted the empty migration file, the database still had the stale revision ID in `alembic_version`.
- **Fix:** Directly cleared it with:
  ```sql
  DELETE FROM alembic_version;
  ```
- **Rule:** Never delete a migration file that has already been applied to a database without also clearing the `alembic_version` table.

## Commands Reference (For This Phase)

```powershell
# Start DB container only
docker-compose up -d db

# Check container health
docker inspect boundary_db --format "Status: {{.State.Status}} | Health: {{.State.Health.Status}}"

# Enable pgvector extension (run once per new DB)
docker exec boundary_db psql -U boundary -d boundary_surveys -c "CREATE EXTENSION IF NOT EXISTS vector;"

# Generate a new migration
$env:PYTHONPATH = "."; .venv\Scripts\alembic revision --autogenerate -m "description_of_change"

# Apply all pending migrations
$env:PYTHONPATH = "."; .venv\Scripts\alembic upgrade head

# Check which tables exist in DB
docker exec boundary_db psql -U boundary -d boundary_surveys -c "\dt"
```
